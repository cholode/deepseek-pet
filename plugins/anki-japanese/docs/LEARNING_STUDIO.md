# 1.2.0 课程记录与原生复习

在“可操作软件”重新安装/导入 1.2.0 后，重新连接并授权工具。插件内容和工具签名变化会使旧授权失效，这是预期行为。主程序版本仍为 1.5.0。

新增 `anki_lesson_record`，在清单中声明为 `learningRecordTool`。授权后，小屋“智能陪伴 → 学习工作室 → 学习计划与记录插件”可以选中该软件关联。宿主在真实课堂完成后同步总结、纠错、实际作答、用时和词表。日志卡暂停，不计为正式复习；生词去重后作为正常卡片进入 Anki。

`sessionId` 经哈希转换为稳定记录键，写入前固定内容，重复请求通过唯一标签恢复。同一课堂中断后不能换一组内容重试；先用原内容完成记录。插件响应丢失时，宿主显示“结果待核查”，用户核查后以同一课堂编号重试。

复习流程改为原生 GUI API：

1. `guiDeckReview` 打开绑定复习牌组，`guiCurrentCard` 取得 Anki 已排到的当前卡。不会通过 `findCards` 的返回顺序自行排卡。
2. 题面展示时调用 `guiStartCardTimer`，同一 token 再次取题不重置计时。
3. 用户回答后 `guiShowAnswer`，读取实际 `buttons` 和 `nextReviews`；显示本卡真正可用的评分和预计间隔。
4. 用户明确自评后 `guiAnswerCard`，由 Anki 原生调度写入历史与真实计时。提交前再核对当前 GUI 卡片和卡片状态，旧 token 不能评分其他卡。
5. 评分请求前持久消耗 token；网络错误不重复提交。用户可在 Anki 自行撤销评分，插件下次取题重新读取状态。

插件新卡上限是额外限制，不改 Anki 牌组配置。若原生队列当前排到新卡而插件额度已满，会停止并说明，不能跳过这张卡私自重排。没有当前卡也不表示所有卡已永久学会，可能在等学习步长。图片、音频和复杂模板仍在 Anki 原卡查看。

`anki_status` 分别提供当天正式复习次数、不同卡片数、Anki 历史记录的用时以及对话/课堂用时。当天指电脑本地自然日，可能与 Anki 自定义换日时间不同。统计最多查询当天候选 2000 张卡，超过时明确提示在 Anki 查看。接口不支持统计时保留连接状态并显示统计错误，不伪造零次成功。

验证：`scripts/anki-native-test.cjs` 仅允许 `test-results/anki-audit/isolated-anki` 下的 `DaFeiYu-20word-Audit` 独立用户，测试脚本作答不代表真实学习表现；不会接触用户正式集合。实际验证结果见 `test-results/anki-audit/native-review-report.json`。
