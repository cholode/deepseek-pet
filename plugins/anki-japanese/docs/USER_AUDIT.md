# 大肥鱼 Anki 插件：20 词流程评估

日期：2026-10-26。对象：当时标记为大肥鱼 1.6.0 的测试构建、Anki 日语插件 1.0.0、实际安装的 Anki 26.09.3 / AnkiConnect v6 接口。2026-10-27 已将主程序版本更正为 1.5.0，插件仍独立维护 1.0.0；本页保留原测试构建编号，不把历史结果冒充新构建的复验。

使用和安装说明见 [插件 README](../README.md)。以下脚本及测试证据路径均以项目根目录为基准。

**结论：真实读写、评分和日志去重能够工作；取卡队列、计时和学习进度仍有已确认的问题。当前版本应先修复这些问题，再作为日常正式复习入口。** 本轮按用户要求评估，以下改进尚未实施，不把功能测试通过等同于学习效果合格。

## 本次实际做了什么

- 在独立 Anki 数据目录和 `DaFeiYu-20word-Audit` 用户中创建 20 张词卡，通过最终打包版小屋的聊天界面、真实 MCP 子进程、真实 AnkiConnect 完成取题、回答、揭示、自评和写入。没有向用户原有牌组或学习历史写入测试记录。
- 原配置的 DeepSeek 服务返回 HTTP 401。用户选择先完成插件与真实 Anki 流程评估，因此改用本地脚本驱动工具调用，学习者回答也按脚本预设。没有验证真实模型的日语纠错、自然对话、响应速度、口语或发音质量。
- 覆盖 20 个不同词，每词至少作答并评分一次；为抵达第 20 个词，共发生 **43 次评分、130 条用户侧聊天消息**（包含开场、取下一题、自评和结束）。并非“20 词全部掌握”：结束时 19 张卡进入复习阶段，1 张仍在学习阶段。
- 首次回答预设为：12 个正常答对、2 个立即答对、2 个迟疑后答对、4 个忘记。后续重复出现统一选择良好。这是测试输入，不能解释成用户正确率。
- 另做原生队列对照、5 秒作答计时，以及真实练习记录保存/重试检查。4 个测试生词和 1 条练习日志成功保存；重试返回相同笔记 ID，没有增加重复卡片；日志卡处于暂停状态。

| 指标 | 实测结果 |
| --- | --- |
| 不同词数 | 20 |
| 真实 Anki 评分记录 | 43：重来 4、困难 2、良好 35、简单 2 |
| 同卡重复评分 | 23 次，距离前次仅 1.504～2.005 秒 |
| Anki 记录的作答耗时 | 43 条全部为 0；另一次明确等待 5 秒的检查也为 0 |
| 完成词卡流程后的插件统计 | 对话 0 分钟；没有正式复习完成数、不同词数或错词汇总字段 |
| 提醒检查 | 仍返回“已经记录 0 分钟”，因为判断只读取对话日志时长 |

脚本执行很快，约 77 秒完成 43 次评分。这不是人类学习时长，也不是模型性能数据。

## 已确认、优先修复的问题

### 1. 取卡绕过了 Anki 的实际出题队列

`core.mjs` 的 `anki_review_next` 用 `findCards` 搜索 `is:due`，直接取结果第一项，再用 `answerCards` 评分。搜索结果不等于此刻应该呈现的队列。

真实记录中，“犬”第一次选择良好后，Anki 安排的学习间隔是 600 秒；1.504 秒后插件又提交了同一张卡的良好评分。“水”首次重来后的间隔为 60 秒，1.661 秒后就再次评分。共 23 次重复全部发生在几秒内。

为排除“Anki 本身允许提前学”的解释，另建“海、山”两张新卡：

| 同一状态下的选择 | 结果 |
| --- | --- |
| “海”评分后实际到期时间 | 距现在约 731 秒（含 Anki 延迟扰动） |
| 大肥鱼下一题 | 再次取到“海” |
| Anki 原生学习界面下一题 | 取到尚未学的“山” |

**改进：** 接入 Anki 原生复习队列，由它决定卡序、学习间隔、提前学习、每日限额和同笔记卡片避让。不能只给搜索增加一个时间过滤器，就声称完整兼容调度。评分计算虽已交给 Anki，出题队列还没有。

**验收：** 同一集合/牌组选卡与原生复习一致；有其他可学卡时不抢先重复未到期卡；没有可学卡时显示下一次可学时间；覆盖埋藏卡、子牌组限额、外部 Anki 复习和跨学习日。

### 2. 复习计时缺失，提醒看不到背词进度

当前 `answerCards` 只传卡片 ID 和评分。本机安装的 AnkiConnect 兼容接口没有传入作答耗时，底层默认 0；实际复习历史也验证了这一点。单独等待 5 秒仍记 0，排除了纯粹由于脚本过快导致的解释。

插件的 `minutesToday()` 只累加已经保存的对话轮次，词卡评分不会进入这个统计。`anki_status` 和提醒也沿用它，因此无法报告这次已经练过 20 词、提交 43 次评分。这里的“对话 0 分钟”本身没有说错，但不足以作为整体学习计划的完成度。

**改进：** 记录题目显示、揭示和评分时间，明确是否包含反馈阅读；停止、挂起和长时间无操作时暂停计时。通过支持耗时的接口或原生 reviewer 写入真实复习耗时；不能用修改数据库或事后伪造历史补数。分别显示“不同词数、评分次数、复习用时、对话用时”，提醒依据用户设置的目标判定。同步读取 Anki 已有学习进度，避免用户在 Anki 完成后仍被当作未学习。

**验收：** 等待 5 秒产生合理非零耗时；长时间离开不计学习；复习与对话不重复计时；当天目标完成后抑制提醒；午夜与 Anki 学习日边界采用明确规则。

### 3. 操作过于依赖聊天指令

本轮每次评分需要“请求下一题 → 输入答案 → 再发一句自评”，43 次评分共发了 130 条用户消息。这个数量与测试脚本的交互方式有关，不代表每位用户必然发 130 条；但界面确实没有专用的显示答案、四档评分、下一题或撤销控件。

**改进：** 保留对话解释，同时提供固定学习卡片区域：题面、回答输入、显示答案、评分按钮、进度和暂停。评分后自动进入下一张可学卡；明确结束时停止。评分按钮走确定的工具调用，减少重复调用模型。支持空格显示答案、数字 1～4 自评，并为初学者提供“忘了 / 想起来了”两档模式。用户仍应决定最终评分。

原生 Anki 已有评分快捷键、下次间隔显示和简化为 Again/Good 的用法，可直接借鉴其操作含义。[Anki 学习说明](https://docs.ankiweb.net/manual/studying)

### 4. 卡片内容与错误信息展示不够完整

实际界面出现“请回忆读音和中文意思はなす”粘连：纯文本转换去掉 `<hr>` / 块元素时没有保留分隔。声音、图片、注音布局等也没有进入当前聊天展示。`cardsInfo` 已返回 `nextReviews`，插件揭示答案时却只给评分名称，用户看不到选择后多久再复习。

当前正式复习记录只保存评分，未结构化保存用户答案、是否使用提示、读音错还是词义错。因此结束总结缺少可靠的错因数据。模型可以看到部分聊天上下文，但状态工具不能稳定提供跨会话错词总结。

**改进：** 显示标准读音、释义和一条合适例句，保留题面与答案分隔；显示 Anki 返回的评分间隔。按需支持媒体和注音。保存实际答案及可追溯的纠错，让用户修正错误反馈。已有笔记应能更新或追加例句，避免去重后永远保留旧解释。

## 从记忆与日语学习角度的建议

1. **先回忆，再看反馈，隔一段时间再检索。** 当前“题面 → 作答 → 揭示 → 自评”的分阶段设计值得保留；先修复几秒内反复出现的问题。检索练习研究支持关注延迟测试，而不能把刚看过答案后的流利复述当作长期掌握。所引用实验研究的是文章材料，并不能证明本项目日语词卡的具体效果。[Roediger 与 Karpicke，2006](https://www.psychologicalscience.org/journals/psychological-science/j.1467-9280.2006.01693.x/)
2. **忘记应选重来；想起但吃力才选困难。** 揭示答案后，避免用“你已经记住了”暗示用户高评分。读音与意思只有一项正确时，要按这张卡事先定义的目标判断。评分规则需在界面中简短解释。[Anki 评分说明](https://docs.ankiweb.net/manual/studying)
3. **把“看懂”和“会用”分开检验。** 根据学习目标增加中文/场景提示→日语、例句填空、听音辨义，而不是所有词一律生成多个方向。兄弟卡之间需要避让，减少前题给后题提示。新词学习可以先有讲解，再进入主动回忆，不能把陌生词测验失败当作使用者不努力。
4. **对话错误转成小而明确的卡片。** 一张卡只检验一个可自评目标；近义词、活用和搭配用具体语境区分。长篇聊天日志继续暂停，只作为查阅记录；日志长度和聊天次数不等同于记忆增长。
5. **复习负担优先于固定塞满新词数。** 20 个词是本次测试范围，不是自动替用户设定的日课。小屋应区分“每日新词上限”和“今天到期复习”，在积压时建议少加新词。效果验证应由真实用户在后续复习日作答，分别观察无提示回忆、错因和用时。本次没有安排新提醒，也没有测量长期保持率。

## Anki 哪些能力还没充分用到

| 能力 | 当前接入程度 | 下一步用途 |
| --- | --- | --- |
| 正式评分、复习历史、下次间隔计算 | 已真实写入，但出题队列不正确 | 优先改用原生队列，保留评分幂等和状态变化检查 |
| FSRS | 评分交给当前 Anki 调度器；插件未读取或呈现 FSRS 启用状态 | 先检测能力，展示目标保持率、负担估计和已有参数优化入口；不擅自启用或重排全库 |
| 下一次复习间隔 | 实际接口已经返回，插件未呈现 | 评分按钮直接显示下次间隔 |
| 卡片计时与学习统计 | 实测耗时为 0，仅有对话分钟 | 接真实计时、不同词数、复习次数、到期负担及历史趋势 |
| 撤销评分、埋藏、暂停、标记难卡 | 未暴露给大肥鱼用户 | 支持误触恢复、不适合当前学习的卡片暂缓、长期难卡重写；不能伪装成自动给分 |
| 音频、图片、注音和卡片模板 | 目前仅纯文本 | 按目标加入听力、读音和语境练习；不把文本纠错声称为发音评测 |
| Cloze、反向卡、兄弟卡避让 | 插件新建的生词仅单向模板 | 用户选择需要的练习方向，并遵守 Anki 的避让规则 |
| 筛选牌组、标签、笔记编辑 | 仅用固定标签去重 | 针对错词查阅或专项练习，并明确是否改变正式调度 |

FSRS 的目标保持率影响复习负担；插件应显示和解释用户现有配置，而不是另算一套“科学时间表”。本次只读取了牌组配置中的相关字段，没有确认或改变用户真实集合的 FSRS 开关。[Anki 牌组选项](https://docs.ankiweb.net/manual/deck-options)

复习次数可以包含同卡多次作答，不能直接当作掌握词数。长期趋势、到期负担和历史表现比一次会话的高分更适合反馈学习进度。[Anki 统计说明](https://docs.ankiweb.net/manual/stats)

## 交付顺序与验证范围

建议顺序：**原生队列 → 真实计时和统一进度 → 学习按钮/自动下一题/撤销 → 内容与媒体 → FSRS 状态和长期反馈**。前两项是已证实的行为问题；其余为体验与能力扩展建议。现有 227 项逻辑测试和模拟后端 GUI 测试没有覆盖真实 Anki 的时序语义，不能用它们替代这轮真实集合验证。

真实模型 HTTP 401 修复后，还需验证：模型是否按用户意图调用工具、是否提前泄露答案、日语纠错是否正确、是否会代评分、取消与恢复是否自然，以及网络延迟下每词的操作成本。延迟保持率需要真实学习者和后续日期的数据，脚本无法替代。

## 证据与复现

- UI 演练脚本：`scripts/anki-user-audit.cjs`。先准备独立真实 Anki 用户及 `test-results/anki-audit/anki-runtime.json`，确认用户为 `DaFeiYu-20word-Audit`；然后运行 `node scripts/anki-user-audit.cjs --scripted-model`。该命令会在隔离用户中新建牌组并写入测试评分，不是只读检查。
- 本轮：`test-results/anki-audit/trial-c4sdNY/report.json`。包含 130 轮往返、20 词表、43 次尝试、真实复习历史和卡片最终状态；时间戳为真实写入时间。
- 原生队列/5秒计时对照：同目录 `queue-probe.json`。真实日志与生词去重/提醒：`record-probe.json`。
- 已查看实际截图：同目录 `words-20.png`。界面能显示题目和评分确认，也可直接观察文本粘连与缺少专用学习控件。
- `report.json` 的 `issues` 是工具阶段异常列表；为空只表示该脚本未遇到提前评分、漏调用等阶段问题，**不表示本评估没有发现产品问题**。
- 测试证据目录被 Git 忽略。原用户的 Anki 数据目录、配置及模型密钥没有被改写；测试使用的密钥副本已清理，脚本模式不需要读取密钥。
