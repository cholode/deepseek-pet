# 架构与实现边界

## 1.4.5 自动日记与补写

`companion/diary-schedule.ts` 用本地日历计算21点截止日、下一日期与待补天数。主进程完成启动后开启轻量定时器，最多30秒重查壁钟；每次只处理最早到期的一天，下一次继续补齐。聊天繁忙、日记操作或休眠期间让出执行，恢复时重新检查。

`DiaryScheduleStore` 在 userData 的 `diary-schedule.json` 保存起始日期、待处理日期、最近完成日、重试时间和一篇待提交正文。先持久化生成结果，再把去重标记和正文原子提交到日期文件，最后推进进度；崩溃发生在任一步都能继续，已提交文件可用标记去重。换目录时先核对上次提交位置，避免在新目录重复写已经完成的旧日记。生成失败保留日期，退避15分钟；休眠/退出取消独立标记，不把恢复时迟到的中断响应误判为网络失败。

自动补记只提取目标日已有对话，不带当前心情。无资料日写如实说明，不消耗模型请求。记录从本版第一次启动的本地日期开始，不凭空补写此前全部历史；原有400条对话保留限制仍生效。

## 1.4.4 日记服务

`shared/diary.ts` 定义白名单请求、日期和配置校验；`companion/diary.ts` 只负责挑选当地日期的桌面对话、建立模型资料或生成离线纪事。`main/diary/files.ts` 负责定位源码根目录、目录验证、限制读写大小和临时文件提交；`DiaryService` 独立管理生成、取消、列表、目录配置和重启恢复，使用同一个 ModelPort 适配器但不依赖聊天协调器和工具端口。

主进程注入模型凭证读取函数、陪伴快照、文件夹选择/打开能力；renderer 仅通过 panel 专属 `diary` IPC 操作允许的日期文件，预览作为纯文本渲染。日记设置单独落入 userData，不改变旧版陪伴数据格式。生成使用点击时快照与日期；服务串行处理变更，并在模型完成和文件提交前检查取消。配置变更不迁移旧文件，退出等待当前操作收尾。

## 1.4.3 聊天 / 状态菜单

`QuickChat` 保留输入与状态两个面板的挂载，仅切换可见性，草稿、输入法状态和发送请求不因切页丢失。菜单通过限定为 `chat/status` 的 IPC 通知 `PetChatWindows`，原生窗口按 320×94 / 320×224 DIP 定位，切回输入时撤销状态卡多占用空间造成的上移。

`pet-chat-status.ts` 只输出当前动作名称、自动活动、模式、语音开关及心情摘要。数据来自既有运行时快照和主进程陪伴存储，按现有 250ms 状态发布节奏检查变化；不会新增模型轮询，也不将完整配置或私人记忆发到快捷窗口。情绪未启用时返回空值，避免显示虚构状态。

## 1.4.2 角色锚点与紧凑输入

`chatAnchors` 将角色命中区域转换为头部、轮廓和脚底屏幕坐标，替代透明窗口外框；`speechBubbleLayout` 输出气泡位置、尖角方向及偏移，`inputBarLayout` 将 320×58 DIP 输入条置于脚下。气泡的 SVG 尖角与文字测量分离，头部位置更新不会反复触发尺寸调整。

`PetChatWindows` 在底部空间不足时记录并临时上移角色，关闭输入框后仅在窗口尚未被用户移动/缩放时恢复。拖动开始时丢弃旧位置记录，防止松手后跳回原处。渲染器的输入条仅保留文本与发送/停止按钮，模型配置和完整历史仍由小屋负责。

## 1.4.1 悬停聊天与流式展示

快捷输入和回复气泡使用两个透明原生窗口，不扩张角色画布。`PetChatWindows` 管理窗口和生命周期，`chat-layout.ts` 单独计算悬停等待、收起延迟与屏幕边界避让。两个窗口均用 `showInactive()` 显示，用户点击后才接收键盘；1.5.0 的气泡改为接收鼠标，支持滚动和选择文字。打开输入框暂缓普通自主活动，仍保留手动互动和拖动。

快捷窗口仅能通过独立 IPC 发送/停止、获取有限聊天状态和打开小屋；完整配置、密钥、记忆管理仍只授权给小屋主框架。气泡支持文本订阅、受限尺寸报告、活动信号、关闭自身和打开经过校验的网页链接。主进程逐一校验所属窗口及主 frame。

`ModelPort.complete` 提供可选正文增量回调，`CompatibleModel` 使用 SSE 适配器处理 UTF-8 网络分包和工具参数。领域层将展示划分为 `streaming`（只更新文字）、`complete`（正文落盘后展示/朗读）、`action`（情绪评价后补动作）三阶段，沿用同一消息 ID；取消通过 AbortSignal 与轮次检查阻止迟到输出。前端不做模拟打字，语音只处理一次完整回复。

### 1.5.0 长回复与 Markdown

后续增加独立的表情数据插件宿主，详见 `src/main/stickers/`。专用工具选择后由 `ToolRouter` 的结果装饰接口附到最终回复，再统一保存和展示；`petsticker:` 只服务目录中已校验的本地 GIF，普通网络图片仍不加载。小屋提供“表情包”入口，插件支持独立导入、设置、版本与许可，不进入软件操作动作情境。

桌面气泡和小屋聊天记录共用 `MarkdownContent`（react-markdown + remark-gfm），渲染标题、列表、引用、代码、表格等。代码块与宽表格独立横向滚动；原始 HTML 不执行，图片仅显示替代文字。网页链接在渲染器与主进程双重校验，仅允许无凭证的 HTTP(S)，由系统浏览器打开，不允许聊天窗口导航或任意协议。

`useMessageScroll` 管理局部滚动容器：在底部时跟随输出，向上阅读后保持位置，可手动回到最新。气泡以稳定消息 ID 区分回复，完整的新消息从开头显示；窗口最大高度仍为 320 DIP。气泡获得焦点或鼠标停留时延后自动关闭；Esc 或关闭按钮记录本条消息 ID，后续流式更新不重新弹出。气泡活动沿用既有用户互动信号，不新增动作执行入口。

## 存储先行

`SettingsStore` 首先读取 `userData/settings.json`，用 Zod 校验全部字段。损坏时备份，使用明确默认值。保存通过串行写队列、临时文件和 rename 完成。主进程是磁盘写入的唯一入口。

`PackStore` 扫描内置资源和用户包，先检查文件类型、目录联接、路径、压缩前大小与图像头，再解析清单、motion、group。每次构建候选 registry，跨引用和通道分析完成后才发给 renderer 预加载。renderer 成功准备纹理后取消旧实例、切换目录、更新图层并释放旧纹理；主进程收到确认后提交资源令牌白名单。失败保留旧目录；坏包不会直接清空其他有效包。

## 单一运行时

`PetRuntime` 只在桌宠 renderer 中创建一次，维护 registry、设置、桌面状态、当前前景实例、幂等接收缓存、隔离组与有界错误/事件缓冲。React 小屋订阅每 250ms 发布的状态，不驱动逐帧动画。

普通驱动、点击绑定、手动预览和智能陪伴进入同一个 `PetControlPort` / 命令入口。来源由本地可信入口绑定，优先级依次为系统 100、手动 80、点击 60、AI 40（智能陪伴启用后可用）、普通 10。低优先级不能抢占；相同或更高优先级取消旧实例。拖动锁住非系统命令，系统通过动作组的 `interaction` 元数据选择拎起/放下动作。

1.3.13 的 `sprite_rig` 使用包内透明组件、支点、层序与有限关键帧；`pet/sprite-rig.ts` 逐组件插值，`Avatar` 复用全身帧动画的布局、命中区与资源生命周期。没有每个动作的 TypeScript ID 分支，也没有动作包代码执行。拖动开始取消当前动作；每个有限周期完成后，由同一 ticker 在拖动仍有效时开启下一实例。重复的桌面位置广播不再取消当前周期；松手、挂起、隐藏和失败走统一清理路径。手动预览仍只播放一个有限周期。

`ActionGroupRunner` 将经过校验的有限动作树编译为时间表：顺序累加偏移，并行共享起点。统一 Pixi ticker 推进所有叶子。每个资源句柄具有幂等 dispose，结束的节点先释放，后续顺序节点再获取通道。任一分支异常会释放所有兄弟，恢复基准姿态并发出唯一终态。实例 ID 阻止旧终态清除新动作。

`NormalBehaviorDriver` 只选择组并提交命令。注入时钟和随机源，按启用、资格、权重、冷却、真实用户空闲、指针、漫游条件过滤，再逐步放宽最近两次历史。冷却从终态开始。暂停/停止清除唯一计时器，并用 epoch 拒绝旧回调。空池安全待机。

## 渲染和交互

1.3.18 的水平惯性由 `pet/drag-inertia.ts` 独立计算。主进程沿用 34ms 鼠标采样，广播原始屏幕 DIP 的 X、单调时钟和手势 ID；不从被工作区夹取后的窗口位置求速度。对速度做 40ms 平滑后计算水平加速度，以移动支点的阻尼摆方程 θ″ = (a/L)cosθ − ω²sinθ − 2ζωθ′ 驱动身体。匀速不持续施力，刹停和反向保留角动量；软限位恢复力与 tanh 视觉压缩避免撞到角度上限时突然停住。第二个弹簧延迟驱动头发、尾巴和腿。积分按实际帧间隔划分为最多 1/240 秒的子步，30/60fps 保持近似一致；限制极端速度和角度，重复/乱序采样不再注入冲量，失去采样后自动收敛，长帧间隔直接清零。

`Avatar` 在每帧先执行动作关键帧，再应用惯性姿态；`sprite-rig.ts` 每次从组件基准重新计算，防止旋转累计。整套组件绕 motion 声明的头顶支点旋转，局部延迟仍绕发根、尾根、腿根。惯性实例属于一次鼠标手势，`ActionGroupRunner` 的有限循环重建不会清除它；松手、隐藏、挂起、固定位置或新手势清零。`rigViewport` 按旋转角度区间的轮廓极值扩展透明窗口，角色不缩小；拖动期间的动作结束/重建保留当前窗口，直到松手再恢复，避免每 3.5 秒收缩一次。可选 `dragInertia` 的参数和组件引用由 schema 校验，没有新增动作 ID 分支、定时器或脚本执行入口。

1.2.0 起，`Avatar` 的站立角色由 `pet/live2d/Live2DRenderer.ts` 加载本地 MOC3、纹理及官方 Core，当前计算 38 个 ArtMesh，使用眼部及口腔剪裁遮罩，渲染到透明 canvas，再交由 Pixi 合成。1.2.8 新增的双侧双眼皮线及原右眼睫毛边缘使用既有左右眼开合参数，跟随同一眼部/头部变换。1.3.0 加入四层嘴部网格与四层泪光网格。模型只有现有 Pixi ticker 一个时钟；睡觉等全身序列播放时完全跳过隐藏模型的更新。隐藏窗口/休眠继续停止 ticker；销毁时释放 Core 模型、MOC 内存、WebGL 缓冲、遮罩纹理和 Pixi canvas 纹理。

`pet/live2d/pose.ts` 把公开节点的关键帧及表情投射到 24 个模型参数；额外位移/缩放作用于对应部件网格，虹膜和眼部遮罩使用相同的头部变换。`shared/expressions.ts` 集中定义 12 种预设及左右眼开合、视线、腮红和模型参数，schema 直接复用 ID 列表。每帧先设置全部面部参数的中性值，再应用当前预设，避免跨动作残留。`ParamBrowForm` 与 `ParamBrowAsym` 驱动原眉毛所在的脸部及刘海网格同步形变，Pixi 不另画眉毛。根节点跳跃、旋转和镜像由 Pixi 处理。适配器不按动作组 ID 分支，外部 JSON 仍由同一个 `ActionGroupRunner` 执行、抢占、取消和清理。前景 pose/face 通道仍优先于待机。

1.3.2 的 `arms.ts` 为肩、肘、腕提供两段连续绑定；原 Core 输出作为输入，未改动原网格或贴图。`arm-art.ts` 生成局部清理和补绘的备用图集，肩关节启动时渐变切换，手臂跨过下巴前切换前景绘制层。`Live2DRenderer` 的面部肤色着色仅作用于指定网格，表情退出时强度归零。`hair-fill.ts` 补绘被手臂遮住的内侧卷发；`steam.ts` 提供有限时长的蒸汽特效。expression 叶子可声明进入/退出时长，Avatar 用平滑包络统一插值原生面部参数与肤色强度，未声明过渡时保持兼容。JSON `super_shy` 组合 pose、face、effect 三个通道，无动作 ID 专用分支，统一执行器负责自然结束、中止和重载清理。

新嘴型由 Cubism 的 `ParamMouthForm/OpenY/Twist` 控制，`ParamMouthActive` 在原嘴与新嘴之间互斥切换。舌头和牙齿使用口腔遮罩；整个嘴部网格与遮罩共用 mouth/head 变换。`ParamEyeSmile` 控制闭眼线弧度，左右眼独立开合；`ParamTear` 控制眼内泪光，泪光随眼睑收拢并受对应眼部遮罩限制。Pixi 仅保留腮红覆盖，不再单独画惊讶嘴。五个新动作仅由 JSON 时间轴组合现有通道。

1.3.1 将腮红的颜色、透明度、位置、半径及柔边放入表情预设，害羞使用加深的双颊柔边晕染；仅在切换表情时重建图形，逐帧继续跟随头部。表情预览通过生产 `Avatar` 合成，包含 Core 模型和 Pixi 腮红，避免预览与桌宠显示不同。

1.2.1 将脖子拆成独立 `Neck` 网格，Cubism 父级为胸口呼吸，时间轴绑定 `body`，不继承头部位移。后发顶端按与模型旋转一致的权重继承头部位移和缩放，权重向发梢衰减至零。头饰、下巴和尾巴残影在原始图层中修正；没有通过缩小动作幅度掩盖残留。`scripts/live2d-cutout-test.cjs` 使用生产渲染类与实际模型验证独立脖子、后发顶部透明、旧尾鳍外缘透明以及尾巴参数隔离，并输出极限姿态与循环帧。

主进程已有的 34ms 鼠标采样额外发送相对窗口的 DIP 坐标，供平滑的双轴视线跟随使用。没有新增 renderer 读取系统鼠标或任意系统 API 的权限。生产 CSP 仅增加 `wasm-unsafe-eval` 以编译可信本地 Core 内嵌 WebAssembly，仍禁止 JavaScript `eval`；用户动作包仍只接受 JSON/PNG/WebP。Live2D 文件是应用静态资源，不属于可导入脚本包。

`Avatar` 使用 PixiJS 8 `Application.init()`、纹理缓存、容器和图形。设计画布 340×420，角色脚底原点固定。`root/body/head/hairBack/hairFront/armLeft/armRight/eyes/mouth/effects` 是公开节点；头部容器带动眼嘴和前发。旋转以度声明，内部转为弧度。

动作通道暂时接管对应待机：pose 不会被呼吸覆盖；face 不会被眨眼覆盖。全身帧动画隐藏分层树，按统一脚底锚点展示序列，完成/取消恢复分层树。按压使用独立覆盖容器，不污染动作基准。

鼠标事件记录按下、移动阈值、指针捕获和松开。单击延迟 260ms 等待双击；拖动启动取消待定单击。矩形命中区通过角色节点变换转换为 DIP，不能用含透明空白的纹理包围盒当头部区域。

主进程每 34ms 采样系统鼠标，只有 ignore 状态变化才调用 Windows 输入开关。拖动时主进程为位置真源，起点和终点立即采样，避免快速拖放在两次轮询之间漏掉位移。自主移动也由主进程插值，取消后保留当前合法位置。

屏幕坐标全部使用 DIP，窗口大小与设计坐标显式变换。设备像素比只用于 canvas 分辨率，不乘入屏幕位置。几何计算包含工作区原点，能处理负坐标和任务栏。显示器变化后选择最近工作区并夹取。

Windows 本机测试采用 `pop-up-menu` 置顶级别。普通 `floating` 在本机返回未置顶，已在实际测试中发现并替换。普通移动和松手后的停留位置限制在工作区，手动拖动允许越界，不反复抢焦点。

1.3.19 手动拖动直接采用屏幕 DIP 坐标，不在每次鼠标采样或拖动画布扩展时夹取工作区。松手先采集最后位置，再将当前窗口还原为站立尺寸的底部中心锚点，对全部显示器工作区求合法矩形，以实际平移距离最小者归位；随后渲染器恢复站立画布。持久化位置同样使用合法站立坐标。失焦、拖动超时和显示器断开走同一结束逻辑；自动散步继续受工作区限制。

## 安全和离线运行

全部 BrowserWindow 使用 `contextIsolation:true`、`nodeIntegration:false`、`sandbox:true`。preload 仅暴露明确函数，主进程校验发送窗口和顶层 frame、命令内容与参数范围。小屋不能调用宠物专用拖动/位移接口，宠物不能打开任意路径或读取任意文件。

`petasset://local/<随机令牌>` 只能读取当前批准包的图像；不传文件系统路径。禁止导航、新窗口、webview 和权限请求。生产 CSP 不开放远程连接、脚本 eval 或任意脚本源。Pixi 的 `pixi.js/unsafe-eval` 名称容易误解：这里导入的是**免 eval 的静态 uniform polyfill**，未放开 CSP。

安装产物没有 Node 调试端口和测试桥接。`scripts/gui-test.cjs` 只在开发时启用 Playwright/CDP，设置独立测试 userData，不进入打包文件。运行程序不读取模型密钥、不分析屏幕、不调用模型、不加载远程页面。

### 1.3.9 逐帧表情叠层

`frame_animation.frameOverlays` 为通用数据结构：画布位置、可见格子宽高、列数、可选留边与图片路径。主进程检查真实图集尺寸及画布边界，catalog 检查图片引用；仍使用既有预算和安全路径，不接受脚本。

`pet/frame-overlays.ts` 为每个叠层创建共享纹理源的 Pixi `Texture` 视图，身体与叠层只计算一次 `frameIndex`。更新视图裁切矩形及 UV，不逐帧复制整图或重新上传纹理。两像素留边提供连续采样，避免缩放时混入相邻格子。dispose/reset/destroy 只销毁临时视图，源图集由统一缓存管理，保证停止、重播、取消及重载后仍可使用。

玩手机保持 96 帧、24fps、4 秒；十个新增动作仅新增 JSON 和表情图集。原身体无损改存 WebP，原生气动作改用同一身体与局部图集。站立入口、点击绑定、随机开关和生命周期继续由统一执行器处理，未增加具体动作 ID 分支。

### 1.2.6 宽姿势窗口与缩放

`frameViewport` 根据序列画布、`displayScale` 和角色基础缩放计算设计窗口，睡姿由 340×420 扩为 502×420。Renderer 通过限于 pet 窗口的 `set-viewport` IPC 通知主进程；只接受整数尺寸、340～1024 宽和 420～1024 高。主进程保持底边中心，夹取至当前显示器工作区，重定基准后继续已有移动/拖动；持久化位置转换回站立窗口坐标。偶数窗口宽度防止重复扩展和收缩积累半像素偏移。

场景缩放移到 Pixi 根节点下的独立 `scene`，使用户大小设置实际作用于人物、特效、气泡和命中区；顶层渲染根节点的缩放此前未作用于最终画面。动作完成、取消、资源重载共用恢复基础窗口的路径。没有新增动作 ID 分支。

桌宠在加载纹理前订阅 runtime 消息，加载期间暂存消息，初始化完成后按接收顺序应用，避免启动时改大小或暂停设置丢失，造成窗口与角色尺寸不一致。

## 软件操作期间的动作情境

`SoftwareService` 仅在真正进入非后台 `session.call` 时通知宿主 `operating(true)`，在调用返回/失败的 `finally` 和 abort 监听中通知一次 `false`，不等待连接清理。连接握手、授权、普通模型请求和后台提醒均不激活此状态。

主进程将 `softwareOperating`、真实输入时间和当前鼠标互动状态传入 `DesktopState`。键盘、鼠标按键/滚轮由 Electron 窗口输入事件记录，受限的 `user-activity` IPC 补充 DOM 输入、粘贴和输入法事件，只报告活动、不传文本；采样覆盖桌宠附近、悬停聊天和可见小屋，包括鼠标穿透模式下的小屋。聊天窗口的开关仍由原悬停策略管理，不把模型忙碌导致的窗口保持误判为用户互动。

通用 `requiresSoftwareOperation` 条件由共享策略同时约束候选池、能力列表和所有命令入口。统一执行器在条件失效时递归取消、复位；普通动作在软件操作期间让出自动候选池，手动/交互动作的优先级保持不变。复用原行为驱动的单一定时器，在操作期间每 250ms 检查空闲门槛，仍尊重随机资格、权重和冷却。内置十二个手机组通过 JSON 启用条件，没有新增动作 ID 分支。
